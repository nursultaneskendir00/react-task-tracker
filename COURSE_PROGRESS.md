### React-список задач

Цель: перенести ключевые возможности прежнего списка задач в декларативный интерфейс React.

Первый этап: завершён. Добавлены состояния `taskText` и `tasks`; контролируемое поле и функция `addTask()` добавляют новую задачу в массив.

Второй этап: завершён. Массив задач выводится через `tasks.map()` в JSX.

Третий этап: завершён. `deleteTask()` через `filter()` удаляет выбранную React-задачу и обновляет интерфейс.

Четвёртый этап: завершён. `useEffect()` сохраняет массив задач в `localStorage`, а начальное состояние `useState()` восстанавливает их после обновления страницы.

Пятый этап: завершён. Стили в `index.css` задают основу страницы, а `App.css` оформляет карточку задач, поля, кнопки и список.

Шестой этап: завершён. Обработчик `onKeyDown` создаёт задачу через `addTask()` при нажатии клавиши Enter.

Седьмой этап: завершён. Каждая задача хранится как объект с `text` и `completed`; клик по тексту меняет статус, а CSS перечёркивает выполненный пункт. Отступ разделяет основные кнопки.

Восьмой этап: завершён. Состояние `filter` и массив `visibleTasks` выводят все, активные или выполненные задачи. Кнопки фильтра меняют режим и показывают текущий выбор цветом.

Девятый этап: завершён. Контейнер `main-actions` использует Flexbox: на широком экране кнопки расположены по краям, а на экране до 480px — одна под другой.

Десятый этап: завершён. `clearCompletedTasks()` через `filter()` удаляет выполненные задачи. Кнопка очистки показывается условно через `some()` и имеет отдельный оранжевый стиль.

Одиннадцатый этап: завершён. Вычисляемые значения `activeTasksCount` и `completedTasksCount` считают активные и выполненные задачи через `filter()` и выводятся рядом с общим количеством.

Двенадцатый этап: завершён. Блок `task-stats` оформлен CSS Grid: три карточки расположены в ряд, а на мобильном экране — вертикально.

Тринадцатый этап: завершён. Условный JSX показывает разное сообщение, если задач нет совсем или выбранный фильтр не нашёл задач. Класс `empty-message` оформляет это сообщение.

Четырнадцатый этап: завершён. Разметка одной задачи вынесена в компонент `TaskItem`; `App` передаёт ему данные и функции через props `task`, `onToggle` и `onDelete`.

Пятнадцатый этап: завершён. Поле ввода и кнопка вынесены в `TaskForm`; компонент хранит локальное состояние текста, отправляет форму через `onSubmit` и передаёт новую задачу в `App` через prop `onAddTask`.

Шестнадцатый этап: завершён. `editTask()` неизменно обновляет текст выбранной задачи, а `TaskItem` переключается между текстом и полем ввода через локальное состояние `isEditing`.

Семнадцатый этап: завершён. `cancelEditing()` возвращает исходный текст и выключает режим редактирования; условная кнопка «Отмена» отображается только во время ввода.

Восемнадцатый этап: завершён. Кнопки редактирования получили отдельные классы и цвета: изменение — зелёное, сохранение — синее, отмена — серая; для каждой настроен `:hover`.

Девятнадцатый этап: завершён. Задача хранит поле `priority`; `TaskForm` передаёт выбранный приоритет в `App`, а `TaskItem` показывает цветной бейдж через объект `priorityLabels` и CSS-классы.

Двадцатый этап: завершён. `priorityOrder` задаёт порядок важности, а цепочка `map()`, `filter()` и `sort()` отображает задачи от высокого приоритета к низкому, не меняя исходный массив.

Двадцать первый этап: завершён. Каждая задача получает `id` через `crypto.randomUUID()`; удаление, смена статуса, редактирование и React `key` используют этот постоянный идентификатор вместо позиции в массиве.

Двадцать второй этап: завершён. Второй `useEffect()` обновляет `document.title` при изменении массива `tasks`, показывая число задач прямо в названии вкладки.

Двадцать третий этап: завершён. Состояние `searchText` управляет полем поиска, а `matchesSearch` внутри `filter()` оставляет задачи, текст которых совпадает с запросом без учёта регистра.

Двадцать четвёртый этап: завершён. Условная кнопка очистки появляется при непустом `searchText`, а её обработчик возвращает поиск к пустой строке через `setSearchText('')`.

Двадцать пятый этап: завершён. Состояние `isDarkTheme` управляет классом `dark-theme`, CSS меняет вид интерфейса, а `useEffect()` сохраняет выбранную тему в `localStorage`.

Двадцать шестой этап: завершён. Новая задача получает `createdAt` через `new Date().toISOString()`, а `TaskItem` условно отображает её в формате `ru-RU`; CSS оформляет дату отдельным классом.

Двадцать седьмой этап: завершён. Управляемый список `sortBy` переключает компаратор `.sort()` между приоритетом, новыми и старыми датами; старые задачи безопасно используют значение `0` вместо отсутствующей даты.

Двадцать восьмой этап: завершён. Начальное состояние `sortBy` читает ключ `sort-by` из `localStorage`, а `useEffect()` записывает новый выбор при каждом изменении.

Двадцать девятый этап: завершён. `resetView()` возвращает фильтр, поиск и сортировку к исходным значениям; условная кнопка появляется только при изменённом представлении и получает отдельный CSS-стиль.

Тридцатый этап: завершён. `changeTaskPriority()` обновляет приоритет по `id`, обработчик передан из `App` в `TaskItem`, а бейдж заменён на управляемый `select`, построенный из `Object.entries(priorityLabels)`.

Тридцать первый этап: завершён. Кнопка удаления вызывает `window.confirm()` и передаёт управление `onDelete()` только после подтверждения пользователя.

Тридцать второй этап: завершён. В режиме редактирования условный блок показывает `text.length`, а отдельный класс `char-count` оформляет счётчик символов. Класс `editing` переносит поле ввода на отдельную строку через `flex-wrap` и `flex-basis`, поэтому текст не сжимается.

Тридцать третий этап: завершён. Атрибут `maxLength={40}` ограничивает название при создании и редактировании, а счётчик показывает формат `N / 40 символов`.

Тридцать четвёртый этап: завершён. `TaskForm` хранит необязательное `description`, передаёт его в `App`, а новая задача сохраняет это поле; `TaskItem` условно показывает описание под названием. `textarea` получила отдельную раскладку и стили для светлой и тёмной тем.

Тридцать пятый этап: завершён. `TaskItem` хранит локальное состояние описания при редактировании, «Отмена» его восстанавливает, а `onEdit` передаёт название и описание в `App`; `editTask()` обновляет оба поля по `id`.

Тридцать шестой этап: завершён. Состояние `priorityFilter` управляет списком приоритетов и участвует в вычислении `matchesPriority` внутри `filter()`. Сброс отображения учитывает и возвращает фильтр приоритета к значению `all`.

Тридцать седьмой этап: завершён. `descriptionFilter` с режимами `all`, `with` и `without` использует `hasDescription` и `matchesDescription` в общей цепочке фильтрации. Сброс отображения учитывает этот новый фильтр.

Тридцать восьмой этап: завершён. Статистика показывает `visibleTasks.length` как число видимых задач, а CSS-сетка переключена на 2 × 2 для четырёх показателей.

Тридцать девятый этап: завершён. Асинхронный обработчик `copyTaskText()` копирует название через `navigator.clipboard.writeText()`, а кнопка копирования получила отдельные CSS-стили.

Сороковой этап: завершён. Состояние `isCopied` временно меняет текст кнопки после успешного копирования; `setTimeout()` через две секунды возвращает исходную надпись.

Сорок первый этап: завершён. `exportTasks()` превращает задачи в JSON, создаёт `Blob`, временную ссылку и запускает скачивание файла `react-tasks-backup.json`; после скачивания ссылка очищается через `URL.revokeObjectURL()`.

Сорок второй этап: завершён. Кнопка «Загрузить задачи» открывает скрытое поле выбора JSON. `FileReader` читает выбранный файл, `JSON.parse()` превращает его в данные, а `try/catch` показывает ошибку для неподходящего файла. Импорт добавляет только задачи с новыми `id`, поэтому повторный выбор одного файла не создаёт дубликаты.

Сорок третий этап: завершён. `importMessage` сообщает, сколько новых задач добавилось после импорта. Поле выбора очищается через `event.target.value = ''`, поэтому пользователь может повторно выбрать тот же JSON-файл; в тёмной и светлой темах сообщение имеет отдельные стили.

Сорок четвёртый этап: завершён. `setTimeout()` очищает `importMessage` через 3000 миллисекунд, поэтому уведомление об импорте не остаётся на странице навсегда.

Сорок пятый этап: завершён. Импорт проверяет, что каждый элемент файла — объект с текстовым `text`, затем через `map()` дополняет отсутствующие поля: `id`, `completed`, `priority`, `description` и `createdAt`. Поэтому старые неполные JSON-копии тоже можно загрузить.

Сорок шестой этап: завершён. Состояние `importStatus` определяет визуальный вид уведомления: `success` для добавленных задач и `empty`, когда новых задач нет. Динамические CSS-классы и отдельные цвета делают результат импорта понятнее в обеих темах.

Сорок седьмой этап: завершён. `clearAllTasks()` спрашивает подтверждение через `window.confirm()` и очищает массив только после согласия пользователя. Красная кнопка видна лишь при наличии задач; экспорт и импорт позволяют безопасно восстановить список после очистки.

Сорок восьмой этап: завершён. Через `filter()` и `.length` вычисляются количества задач с высоким, обычным и низким приоритетами. Показатели выводятся в `task-stats` и мгновенно обновляются при создании и изменении задач.

Сорок девятый этап: завершён. `completionPercent` защищён от пустого списка условием `tasks.length === 0`, а в остальных случаях вычисляет и округляет долю выполненных задач через `Math.round()`.

Пятидесятый этап: завершён. Вложенные элементы `progress-bar` и `progress-bar-fill` выводят наглядный прогресс через inline-стиль `width`. CSS задаёт форму, цвета светлой и тёмной тем и плавное изменение ширины.

Пятьдесят первый этап: завершён. `showImportantTasks()` одним действием выставляет фильтры активных и высокоприоритетных задач, а также сбрасывает поиск и фильтр описания. Кнопка быстрого режима имеет отдельные CSS-стили, а «Сбросить фильтры» возвращает обычный вид.

Пятьдесят второй этап: завершён. `importantActiveTasksCount` через одно условие с `&&` считает невыполненные высокоприоритетные задачи. Значение выводится в подписи кнопки быстрого фильтра и обновляется при изменениях задач.

Пятьдесят третий этап: завершён. `completeVisibleTasks()` извлекает `id` текущих видимых задач через `map()`, а затем меняет через `setTasks()` только совпавшие объекты. Кнопка отображается, когда среди видимых задач есть активные, и скрывается после завершения всех.

Пятьдесят четвёртый этап: завершён. `deleteVisibleTasks()` запрашивает подтверждение, получает `id` задач из текущего `visibleTasks` и через обратную проверку `!includes()` оставляет скрытые задачи. Красная кнопка доступна только при непустом результате фильтра.

Пятьдесят пятый этап: завершён. `activateCompletedTasks()` проходит по массиву через `map()` и меняет `completed` на `false` только у выполненных задач. Синяя кнопка доступна при наличии выполненных задач и скрывается, когда их не остаётся.

Пятьдесят седьмой этап: завершён. `toLocaleString('ru-RU', options)` показывает дату создания в русском формате. Объект настроек задаёт числовой день и год, полное название месяца, а также часы, минуты и секунды двумя цифрами.

Пятьдесят восьмой этап: завершён. Фильтр даты получил режим `week`: код рассчитывает точку семь дней назад через `setDate()`, сравнивает объекты `Date` оператором `>=` и включает только недавние задачи.

Пятьдесят девятый этап: завершён. `showTodayTasks()` одним действием очищает поиск и остальные ограничения, устанавливая `dateFilter` в `today`. Отдельная кнопка с CSS-стилями включает этот быстрый режим, а сброс фильтров возвращает обычный список.

Шестидесятый этап: завершён. Новый режим `alphabet` использует `localeCompare(..., 'ru')`, чтобы сортировать названия задач по русскому алфавиту. Он работает с уже существующим `sortBy` и поэтому сохраняется в `localStorage`.

Шестьдесят первый этап: завершён. Режим `alphabet-reverse` вызывает `localeCompare()` с переставленными местами аргументами, поэтому сортирует названия от Я к А. Новый вариант использует уже существующее сохранение `sortBy`.

Шестьдесят второй этап: завершён. Быстрые кнопки «Высокие», «Обычные», «Низкие» и «Все» меняют тот же `priorityFilter`, что и выпадающий список. Условный `className` подсвечивает выбранную кнопку, а CSS Grid располагает элементы сеткой 2 × 2.

Шестьдесят третий этап: завершён. Быстрые кнопки «С описанием», «Без описания» и «Все» синхронизированы с `descriptionFilter` и выпадающим списком. Активное значение получает отдельный класс и подсветку, а CSS Grid располагает три кнопки в ряд.

Шестьдесят четвертый этап: завершён. Быстрые кнопки «Все даты», «Сегодня» и «7 дней» используют общее `dateFilter` с выпадающим списком. Условный `className` и CSS Grid создают синхронизированную группу, где выбранный период выделяется оранжевым.

Шестьдесят пятый этап: завершён. Событие `keydown` на объекте `window` вызывает сброс фильтров по клавише `Escape`. `useEffect` подключает слушатель при запуске компонента, а функция очистки с `removeEventListener` отключает его при удалении компонента.

Шестьдесят шестой этап: завершён. Медиа-запрос `@media (max-width: 480px)` меняет сетку быстрых кнопок описания и даты на одну колонку. Поэтому на маленьком экране элементы не сжимаются, а располагаются вертикально.

Шестьдесят седьмой этап: завершён. У полей названия, описания и приоритета появились `aria-label`. Они не меняют внешний вид, но дают программам чтения с экрана понятные названия элементов формы.

Шестьдесят восьмой этап: завершён. Поля названия, описания и приоритета обёрнуты в контейнеры `.form-field` с видимыми элементами `label`. Связка `htmlFor` и `id` связывает подпись с полем, а Flexbox и `flex-basis: 100%` управляют расположением формы.

Шестьдесят девятый этап: завершён. Счётчик `{text.length} / 40` показывает количество символов в поле создания задачи. `maxLength={40}` ограничивает ввод, а отдельный CSS-класс оформляет подсказку под полем.

Семидесятый этап: завершён. Условный `className` добавляет классу счётчика `near-limit`, когда `text.length >= 35`. Составной CSS-селектор `.character-count.near-limit` выделяет предупреждение оранжевым цветом.

Семьдесят первый этап: завершён. Под текстовой областью описания добавлен счётчик `{description.length} / 120`. Он использует состояние `description` и уже созданный класс `character-count`.

Семьдесят второй этап: завершён. Счётчик описания получает класс `near-limit`, когда `description.length >= 110`. Он использует тот же CSS-стиль предупреждения, что и счётчик названия задачи.

Семьдесят третий этап: завершён. Функция `clearForm` сбрасывает состояния `text` и `description`, а кнопка с `type="button"` вызывает её без отправки формы. Отдельный класс оформляет кнопку очистки серым цветом.

Семьдесят четвёртый этап: завершён. Производная переменная `isFormReady` проверяет название задачи без пробелов. Свойство `disabled={!isFormReady}` запрещает отправлять пустую форму, а CSS-псевдокласс `:disabled` визуально показывает это состояние.

Семьдесят пятый этап: завершён. Условный рендеринг `!isFormReady && (...)` показывает подсказку, когда название задачи не заполнено. Класс `.form-hint` располагает сообщение на отдельной строке формы и оформляет его цветом.

Семьдесят шестой этап: завершён. Функция `fillExampleTask` меняет сразу три состояния формы — название, описание и приоритет. Кнопка с `type="button"` вызывает её без отправки формы и имеет отдельное оформление.

Семьдесят седьмой этап: завершён. `clearForm` проверяет заполненность названия и описания через переменную `hasText`. `window.confirm` запрашивает подтверждение, а `return` оставляет поля без изменений при отмене.

Семьдесят восьмой этап: завершён. Хук `useRef` сохранил ссылку на поле названия через `ref={taskInputRef}`. После успешной очистки `taskInputRef.current.focus()` возвращает туда курсор, ускоряя создание следующей задачи.

Семьдесят девятый этап: завершён. После добавления задачи `handleSubmit` очищает форму и вызывает `taskInputRef.current.focus()`. Это позволяет сразу вводить следующую задачу без дополнительного клика.

Восьмидесятый этап: завершён. Обработчик `onKeyDown` формы распознаёт `Ctrl` + `Shift` + `E` и вызывает `fillExampleTask`. Для проверки физической клавиши используется `event.code === 'KeyE'`, поэтому сочетание работает и в русской раскладке.

Восемьдесят первый этап: завершён. Внутри кнопки примера появился элемент `span` с сочетанием клавиш. Вложенный CSS-селектор `.example-form-button .shortcut-hint` располагает подсказку на второй строке и делает её менее заметной, чем основной текст.

Восемьдесят второй этап: завершён. Состояние `showShortcutHint` управляет условным отображением подсказки. Функциональное обновление `setShowShortcutHint((currentValue) => !currentValue)` переключает состояние, а тернарный оператор меняет текст кнопки.

Восемьдесят третий этап: завершён. Начальная функция `useState` читает настройку подсказки из `localStorage`, а `useEffect` сохраняет каждое её изменение. Поэтому выбор пользователя сохраняется после перезагрузки страницы.

Восемьдесят четвёртый этап: завершён. Функция `resetShortcutHint` возвращает состояние подсказки к `true`, а эффект автоматически сохраняет обновлённое значение. Отдельная кнопка позволяет вернуть настройку по умолчанию.
